# --- Core (used by root main.py) ---
opencv-python>=4.9
numpy>=1.26
mss>=9.0
pyautogui>=0.9.54

# --- OCR (text_detection.py) ---
# pytesseract is just a Python wrapper - it needs the actual Tesseract OCR
# engine installed separately (it's not a pip package):
#   Windows: winget install UB-Mannheim.TesseractOCR   (or the installer at
#            https://github.com/UB-Mannheim/tesseract/wiki - default install
#            path is auto-detected by text_detection.py)
#   macOS:   brew install tesseract
pytesseract>=0.3.10

# OPTIONAL, Windows only, but strongly recommended: tesserocr talks to the same
# Tesseract engine in-process instead of launching a new tesseract.exe subprocess
# per call. Measured ~3.5-4.5x faster against real gameplay (~0.1-0.26s vs
# ~0.42-0.6s per OCR call) - text_detection.py uses it automatically if installed,
# and falls back to pytesseract above if not, so this is safe to skip.
# No PyPI wheel exists for Windows (only a source dist needing a C++ build
# toolchain), so install a prebuilt wheel instead - pick the one matching your
# Python version/architecture from:
#   https://github.com/simonflueckiger/tesserocr-windows_build/releases/latest
# e.g. for Python 3.14 64-bit:
#   python -m pip install "https://github.com/simonflueckiger/tesserocr-windows_build/releases/download/tesserocr-v2.10.0-tesseract-5.5.2/tesserocr-2.10.0-cp314-cp314-win_amd64.whl"
# Not listed as a plain requirement above since there's no single line that
# installs the right wheel for every Python version - see text_detection.py's
# tessdata-path detection if a different Tesseract version needs the tessdata
# folder pointed somewhere other than the Windows default install location.

# --- Overlay (overlay.py, main.py's quit hotkey) + legacy scripts (legacy/) ---
keyboard>=0.13.5

# Windows-only: provides win32gui/win32con used by overlay.py (click-through window) and
# legacy/Window_Capture.py. The transparent overlay itself is also Windows-only right now
# (see overlay.py) - on other platforms main.py falls back to a plain debug window.
pywin32>=306 ; sys_platform == "win32"

# --- Frame source (frame_source.py) ---
# Windows-only, and OPTIONAL: bettercam captures via DXGI Desktop Duplication (the GPU
# already holds the composited desktop) instead of asking GDI to re-blit it. Measured at
# 1920x1080, GDI's BitBlt alone is 12.4ms of the 13.6ms mss spends per frame, and this
# replaces essentially all of it - the capture thread went 15.3 -> 7.0 CPU-ms per frame.
# frame_source.py uses it automatically when present and falls back to mss when it is not
# (or if DXGI fails mid-session), so the pipeline runs either way - just slower without it.
bettercam>=1.0 ; sys_platform == "win32"

# --- Monster detection experiments (tools/benchmark_detector.py,
#     tools/zeroshot_check.py) - DEVELOPMENT ONLY, NOT INSTALLED ABOVE ---
# Deliberately not plain requirements: these are heavy (torch alone is well over
# a gigabyte) and the pipeline never imports any of them. Both scripts print the
# exact install command and exit cleanly when one is missing, so skipping this
# whole section costs you nothing except the ability to run those two tools.
# See docs/monster_detection_plan.txt.
#
# Speed benchmark - pick the onnxruntime build matching your hardware:
#   python -m pip install onnxruntime              # CPU, works everywhere
#   python -m pip install onnxruntime-directml     # any DX12 GPU (Windows)
#   python -m pip install onnxruntime-gpu          # NVIDIA CUDA
# Plus, ONE TIME, to download and export the models to ONNX:
#   python -m pip install ultralytics
# NOTE: installing ultralytics DOWNGRADES torch to the +cpu build, silently
# undoing a CUDA torch install. Reinstall the CUDA build afterwards if you want
# GPU for tools/zeroshot_check.py or tools/train_monster.py. Observed 2026-09-03.
#
# Training (tools/train_monster.py) needs the same ultralytics + torch. Frame
# capture (tools/capture_frames.py) needs only mss + keyboard, both already
# listed above, so collecting data costs no extra install at all.
#
# Zero-shot experiment (OWLv2 via transformers):
#   python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
#   python -m pip install transformers pillow scipy
# scipy is NOT optional and NOT listed by transformers as a hard dependency -
# OWLv2's image processor imports it lazily inside resize(), so it fails only
# once you actually run a detection, several minutes and a 600MB model download
# in. Verified on transformers 5.16.1 / torch 2.14.0. For GPU (this machine has
# an RTX 5070) install a CUDA torch build instead of the +cpu one above; CPU
# inference measured ~3.2s per call, which is auto-labeller territory, not live.
#
# NOTE for when this graduates from experiment to shipped feature: the RUNTIME
# dependency is onnxruntime ONLY. ultralytics/torch stay development-only, used
# by tools/train_monster.py to build the model, never by main.py to run it.
